# 声音音高检测（预览版）设计

日期：2026-11-10
状态：待实现
范围：Oyama's HRT Tracker 的 v1 预览功能

## 1. 为什么做

跨性别用户在做 HRT 和嗓音训练时，很难知道自己有没有变化。音高（fundamental frequency，F0）是最直观、也最容易在家测量的指标之一。这个功能让用户对着手机说一小段话，得到一个「离自己选择的目标有多近」的分数，并把每次结果留在本机，方便看趋势。

它不是「性别鉴定器」，也不是嗓音治疗的临床评估。它只回答一个问题：**这次说话的中位音高，离你当前选择的目标方向有多近？**

## 2. 用户与场景

- 女性化 HRT / 女性化嗓音训练的用户：希望音高逐步升高。
- 男性化 HRT / 男性化嗓音训练的用户：希望音高逐步降低。
- 非二元或目标不是二元嗓音的用户：可以使用，但分数只代表「当前 HRT 模式对应的方向」，不代表个人目标。文案必须说明这一点。

场景：用户在安静的房间里，打开「声音」页，读一句固定的句子，5 秒后看到分数、音高和趋势。每周测一次即可，不需要每天测。

## 3. 目标与非目标

### 目标

1. 用手机/电脑麦克风采集 5 秒语音，在本机计算中位 F0。
2. 根据应用已有的 HRT 模式（`transfem` / `transmasc`）自动决定分数方向，不新增设置。
3. 给出可解释的分数、分档、实测 Hz 和范围，而不是黑盒「性别百分比」。
4. 把派生数据（不含音频）按模式存到本机，展示历史趋势。
5. 麦克风权限、太吵、太轻、无声等状态都有清楚的中文提示。
6. 让生产环境的同源页面可以使用麦克风：worker 的 `Permissions-Policy` 从 `microphone=()` 改为 `microphone=(self)`，camera/geolocation 保持关闭。

### 非目标（v1 不做）

- 不保存、不上传音频；不做云端同步、备份导出。
- 不做共鸣（formant）、语调、语速、气声等分析；这些对「听起来像不像」很重要，但 v1 只做音高。
- 不做「passing」判断，不给「你听起来像男/女」的结论。
- 不替代嗓音治疗师；不根据分数建议用药或手术。
- 不做实时连续音高曲线（只做录音中的粗略实时读数 + 录完后的统计）。
- 不做 Home 大卡片/新底部 tab；v1 从设置页和首页的文字入口进入。入口后续可以升级。

## 4. 证据

音高是合理的首个指标，但不是全部：

- **Boogers 2022（PMID 36371270）**：手机上的 Voice Tools / Voice Pitch Analyzer 与临床 LingWAVES 的 F0 结果显著相关；45 名参与者中 20 名是跨性别者，朗读标准段落。说明手机麦克风测 F0 用于追踪是可行的。
- **Hardy 2020（PMID 30503396）**：40 名说话者、20 名听评者；平均 F0 是唯一能改变「被听成女性/模糊/男性」几率的声学指标；平均 F0、/i/ 的共振峰和声压级共同预测男性化—女性化程度。说明音高重要，但不是全部。
- **Nygren 2016（PMID 26678122）**：50 名跨性别男性使用睾酮；平均 F0 在 3/6/12 个月显著下降，12 个月平均 125 Hz；个体差异很大，嗓音满意度与更低的 F0 相关。
- **Ma 2026（PMID 42567716）**：14 名跨性别男性青少年/青年；说话 F0 在 3 个月下降（平均 -32.9 Hz），9 个月趋于平台；持续元音 F0 更早（2 个月）下降；TVQ 从 51.3 改善到 26.5。
- **Kim 2020（PMID 32104050）**：女性化嗓音不等于单纯提高音高；训练/手术是主要手段。
- **Bush 2024（PMID 35382956）**：21 名跨性别/非二元用户的质性研究；他们需要反馈、可追踪性、自动目标，以及音高之外的训练内容。
- **Simon 2026（PMID 38158296）**：Bensoussan 等人的 AI 用短手机样本给出 0–100% 的「女性化」评分，并用 100 条录音（50 cis 男/50 cis 女）对听评者验证。说明「分数」有先例，但 v1 选择可解释的 F0 规则，不用黑盒模型。
- **Berg 2017（PMID 27370073）**：2,472 名 40–79 岁参与者；对话 F0 男性 111.8 Hz / 女性 168.5 Hz；课堂朗读 130.2 / 198.0；喊叫 175.5 / 246.2。说明 F0 随任务、年龄、语言变化，所以固定任务是必要的。
- **Demirhan 2016（PMID 26223964）**：土耳其年轻成年人持续元音；女性 239.78/251.97/250.29 Hz，男性 127.11/137.23/134.15 Hz。说明不同语言/元音的绝对值不能直接套用。

## 5. 分数模型

用户提出的 150 Hz / 200 Hz 不是「男性平均 / 女性平均」，而是一个以 150 Hz 为中点的对称轴。为了让 80/60/20/-20 这些档位在两种模式下都成立，采用：

```
raw = clamp(((F0 - 150) / 50) * 100, -100, 100)
transfem  的 score = raw
transmasc 的 score = -raw
```

含义：

| 中位 F0 | raw  | transfem score | transmasc score |
| ------- | ---- | -------------- | --------------- |
| 100 Hz  | -100 | -100           | +100            |
| 125 Hz  | -50  | -50            | +50             |
| 150 Hz  | 0    | 0              | 0               |
| 175 Hz  | +50  | +50            | -50             |
| 200 Hz  | +100 | +100           | -100            |

分数永远「越高越接近当前目标」。分档（两种模式共用，因为分数已经按模式翻转）：

| score  | 文案 key             | 中文         |
| ------ | -------------------- | ------------ |
| >= 80  | `voice.bucket.great` | 很不错       |
| >= 60  | `voice.bucket.good`  | 还不错       |
| >= 20  | `voice.bucket.keep`  | 继续努力     |
| >= -20 | `voice.bucket.needs` | 需要勤加练习 |
| < -20  | `voice.bucket.start` | 练习刚刚开始 |

注意：分数是连续值，±5 的变化可能只是当天嗓子状态、录音距离或环境噪声，不应被解释为「退步」。UI 要展示实测中位 Hz 和 p5–p95 范围，避免只盯着一个整数。

## 6. 录音协议（构建者决定）

**v1 采用固定句子朗读，5 秒。** 理由：这是追踪工具，跨次可比性比自然聊天更重要；Berg 2017 也说明任务会显著改变 F0。自由说话留到 v2，作为另一种模式。

- 中文句子（zh）：`今天天气很好，我准备出门走一走，顺便买点东西。`
- 英文句子（en）：`The north wind and the sun were disputing which was the stronger.`
- 俄语句子（ru）：`Сегодня хорошая погода, я собираюсь немного прогуляться и купить кое-что по дороге.`
- 乌克兰语句子（uk）：`Сьогодні гарна погода, я збираюся трохи прогулятися й купити дещо дорогою.`
- 繁体中文 / 粤语：回退到 zh 句子（v1 接受简体；后续可补 zh-TW/yue 句子）。日/韩/土：回退到 en 句子。
- `passageId` 记录实际朗读的文本：`'zh' | 'en' | 'ru' | 'uk'`。历史按 `passageId` 分开，避免不同语言的分数混在同一条趋势里。
- 页面显示句子，用户按「开始」后朗读；5 秒自动停止，也可以提前停止。
- 麦克风约束：`echoCancellation: false, noiseSuppression: false, autoGainControl: false`，单声道。
- 录音期间显示计时、电平条和粗略实时 Hz（约 5 次/秒），让用户知道麦克风在工作。

## 7. 音高算法

纯 TypeScript，不新增依赖。

1. 用 `AudioContext` + `AnalyserNode`（`fftSize = 4096`）取时域帧；每 25 ms 取一次，帧之间重叠，保证覆盖。
2. 对每帧做去直流、降采样到约 16 kHz（简单平均抽取；音高检测不需要全带宽）。
3. 用 YIN（累积均值归一化差分函数）在 70–500 Hz 范围找基频：
   - 差分函数 `d(tau)`；
   - 累积均值归一化 `d'(tau)`；
   - 第一个低于阈值 0.15 的局部极小值；
   - 抛物线插值得到亚采样精度；
   - 返回 `{ f0, clarity }`，`clarity` 用 `1 - d'(tau)` 或类似量。
4. 只接受满足以下条件的帧：
   - `f0` 在 70–500 Hz；
   - `clarity` 高于阈值（约 0.8；与 YIN 阈值对应）；
   - 帧 RMS 高于当前录音的噪声底（取 RMS 的 20 分位数 × 3，且不低于 0.004）。
5. 聚合：
   - 中位 F0（主分数）；
   - p5 / p95（展示范围）；
   - 有效帧比例（voiced ratio）；
   - 有效帧数。
6. 质量门槛：有效帧比例 < 30% 或有效帧 < 20 时，不保存，提示「声音太小/环境太吵，再试一次」。
7. 八度错误：YIN 的首个阈值内极小值通常能避开；中位数聚合再吸收孤立错误。测试里要用含谐波的合成信号验证不会把 120 Hz 听成 60/240 Hz。

实现位置：

- `src/domain/voice/pitch.ts`：`detectPitch(frame, sampleRate)`、`summarizePitch(frames, sampleRate)`、`hzToScore` 不在这里（放 score.ts）。
- `src/domain/voice/score.ts`：`scoreFromF0(f0, mode)`、`bucketForScore(score)`、常量。
- 纯函数，不依赖 DOM，便于 Vitest 用合成正弦波测试。

## 8. 数据与隐私

- 只存派生数据，不存音频。
- 账号与模式命名空间：用 `modeKeyFor(owner, mode, 'voice-checks')`，其中 `owner = user?.id ?? 'local'`，与 `useAppData` 的规则一致。signed-out 的 key 是 `hrt-voice-checks`（transfem）和 `hrt-masc-voice-checks`（transmasc），登录后是 `hrt-u<id>-voice-checks` / `hrt-u<id>-masc-voice-checks`。不沿用设计早期的裸 `voice-checks-v1:${mode}`，否则共享设备上第二个账号会看到第一个账号的历史。
- 在 `src/hooks/useAppData.ts` 的 `MODE_SUFFIXES` 里加入 `'voice-checks'`，让 `adoptSignedOutData` 在首次登录时把 signed-out 记录移入账号命名空间（与其它健康数据一致）。
- 记录结构：
  ```ts
  interface VoiceCheck {
    id: string;
    at: number; // epoch ms
    medianF0: number;
    p5: number;
    p95: number;
    score: number; // -100..100，已按模式翻转
    voicedRatio: number;
    durationMs: number;
    passageId: 'zh' | 'en' | 'ru' | 'uk';
  }
  ```
- 每个模式最多保留 100 条（所有 passage 合计）；超出丢弃最旧的。
- 页面提供「清除本机声音记录」：清除**当前 owner 的两种模式**（transfem + transmasc）的 key，用现有确认对话框；确认文案说明「两种模式都会清除，且不能撤销」。账号删除后 key 会留在该账号命名空间里（与现有本地健康数据的行为一致），登出后不可见。
- 不进入云备份/导出（v1 明确不做；后续如果要，需要先设计备份 schema 的迁移）。
- 麦克风流在停止、离开页面、组件卸载时都必须 `track.stop()`；`AudioContext.close()`。

## 9. 界面

新页面 `src/pages/Voice.tsx`，view key `voice`，归在 `settings` tab（`VIEW_TAB.voice = 'settings'`），同时通过 `ALSO_UNDER.voice = 'home'` 可从首页打开；这样从哪一页进入，返回键就回到哪一页。从两处进入：

1. 设置 > 常规 > 模型区块下方新增一行「声音」。
2. 首页图表下方的链接行，在「预测」旁边加「声音检测」文字链接（`headerActionAccent` 样式）。空状态页也加一个次级链接，保证没有用药记录的用户能找到。

页面结构：

- `PageHeader`，标题「声音」，返回设置/首页（按导航栈）。
- 顶部模式说明：`当前：女性化目标` / `当前：男性化目标`，副文案「跟随设置里的 HRT 模式；只比较音高，不代表全部嗓音特征」。
- 说明卡：为什么测、怎么测、5 秒、安静环境。
- 句子卡：大字显示固定句子，旁边有「试读」？v1 不需要播放音频。
- 录音按钮：大按钮，麦克风图标；录音中变成「停止」，显示 5 秒倒计时/进度环；实时 Hz 小字 + 电平条。
- 结果卡（录完自动出现）：
  - 大号 `+72` / `-35` 分数；
  - 分档文案；
  - `中位 178 Hz`、`范围 165–192 Hz`；
  - 一条水平轴：左端「离目标更远」，右端「离目标更近」，标记当前分数；轴下方小字注明目标方向（更高/更低）。
  - 「再测一次」。
- 历史：
  - 只显示当前 `passageId` 的记录（句子变了，分数就不可比）；最近 12 条，日期 + 分数 + 中位 Hz；
  - 一个简单 SVG 折线图（score 随时间，0 中线），不引入图表库；
  - 空状态文案说明「当前语言还没有记录；切换语言后历史会按朗读文本分开」。
- 页脚：
  - 免责声明：「这是手机麦克风的音高估算，不是嗓音治疗评估。音高只是声音的一部分；共鸣、语调、说话方式同样重要。喉咙痛就停止。」
  - 「依据」折叠区：列出 3–5 条 PMID 链接（Boogers 2022、Hardy 2020、Nygren 2016、Kim 2020、Bush 2024）。
  - 「清除本机声音记录」。

无障碍：

- 录音按钮有 `aria-label`；录音状态用 `aria-live="polite"` 报「正在录音」「录音完成」。
- 结果数字和分档在一个 `aria-live` 区域；不要让屏幕阅读器读实时 Hz 的每一次变化（`aria-hidden` 或节流）。
- 所有可点区域至少 44px；遵守现有 `tap-target` 习惯。

## 11. 测试与验收

单元测试（Vitest）：

- `scoreFromF0`：100/125/150/175/200 Hz 在两种模式下的值；clamp；边界 80/60/20/-20。
- `bucketForScore`：各档位边界。
- `detectPitch`：110/150/200/250 Hz 合成正弦波（48 kHz，带轻微噪声）误差在 ±2 Hz；静音返回 null；白噪声返回 null 或低 clarity；含二次谐波的 120 Hz 不会跳八度。
- `summarizePitch`：中位数、p5/p95、voiced ratio；不足帧数返回 null。
- worker 安全头：`Permissions-Policy` 包含 `microphone=(self)`，不包含 `microphone=()`；camera/geolocation 仍为 `()`。
- 翻译：新增的 `voice.*` key 在 en / ru / uk 三包中完全一致（现有 `tests/translations.test.ts` 的约定）；zh 也补齐。

构建/类型：

- `npm test`
- `npm run build`（或仓库现有的 typecheck/build 脚本；以 package.json 为准）

手工验收（需要真实麦克风）：

- Chrome/Safari 各测一次：允许权限、读句子、5 秒停止、结果合理、刷新后历史还在。
- 拒绝权限、静音、太吵三种情况各看一次提示。
- 切换 HRT 模式后历史分组正确、分数方向翻转。
- Tauri 桌面版至少试一次；失败则确认提示可读，不崩溃。

## 12. 风险

- **生产环境权限头**：`worker.ts` 目前对所有响应发 `microphone=()`，这会直接禁掉部署版网页的麦克风。必须改成 `microphone=(self)` 并重新部署，否则功能只在本地开发有效。这是本功能的上线前置条件。
- **Tauri 桌面麦克风**：Linux WebKitGTK / Windows WebView2 / macOS WKWebView 的 `getUserMedia` 支持不一致；这是 v1 最大不确定性。网页版是主路径；桌面版失败要有清楚提示，v1 不改 `src-tauri`。
- **音高 ≠ 性别**：文案必须避免「你听起来像男性/女性」；分数只对应当前选择的目标方向。
- **固定句子的语言覆盖**：v1 有 zh/en/ru/uk；zh-TW/yue 回退 zh，ja/ko/tr 回退 en。对没有本地句子的语言不理想，但比错误翻译好；历史按 `passageId` 分开。
- **HRT 模式的语义**：模式是「HRT 方向」，不是「嗓音目标」。非二元用户、或做女性化 HRT 但不做嗓音训练的用户，分数可能不符合个人目标；文案要明确「这是当前模式对应的方向，不是对你的评价」。
- **手机麦克风差异**：不同设备的频响和自动处理会影响 Hz；禁用 AGC/降噪后相对可比，但跨设备比较仍不可靠。趋势只建议在同一设备上看。

## 13. 构建者决定（可在实现前改）

- 固定句子 vs 自由说话：选固定句子，理由是可比性；如果用户更想要自然说话，v1 可以改成「自由说 5 秒」，但趋势会更飘。
- 只存 localStorage，不接云备份：v1 预览，避免动备份 schema。
- 存储按 `modeKeyFor(owner, mode, 'voice-checks')` 做账号 + 模式命名空间；把 `'voice-checks'` 加入 `MODE_SUFFIXES`，让首次登录沿用 `adoptSignedOutData`。
- 生产 worker 的 `Permissions-Policy` 改为 `microphone=(self)`；camera/geolocation 保持 `()`。这是功能上线的前置条件。
- 翻译范围：zh/en/ru/uk 补齐所有 `voice.*` key（ru/uk 是现有测试要求）；ja/ko/tr 回退 en。句子只有 zh/en/ru/uk；zh-TW/yue 回退 zh 句子。
- 历史按 `passageId` 过滤，不混合不同语言的句子。
- 「清除本机声音记录」清当前账号的两种模式。
- Tauri 桌面版 v1 不修改 `src-tauri`，失败时提示用浏览器版；网页版是验收主路径。
- 「录音中切换模式」在当前导航下不可达，只保留 hook 的防御性检查，不加跨标签页监听。
- 入口放设置 + 首页文字链接，不新增底部 tab。
- 分档边界按用户给的 80/60/20/-20；`< -20` 统一为「练习刚刚开始」。
- 不做实时音高曲线，只做录音中的粗略读数和录后统计。
