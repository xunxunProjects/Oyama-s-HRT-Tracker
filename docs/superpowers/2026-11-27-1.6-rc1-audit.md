## Findings

### F-01 — Full suite flaky under load — Important — window rc2–rc5

- Evidence: `npm test` baseline run fails with 5000 ms timeouts in
  `tests/regressions.test.ts` ("mipd: a higher single lab never gives a lower
  curve") and `tests/routes.test.ts` ("TC injection: exposure equals F·D/k3…").
  Re-running those two files alone: 139/139 pass. Logs in
  `/tmp/opencode/hrt-1.6-rc-audit/test-baseline.log`.
- Impact: CI is not deterministic; a real regression can be hidden by a flaky
  timeout, and contributors learn to re-run rather than read failures.
- Fix idea: raise the timeout for those simulation tests or isolate them from
  parallel workers; add a repeat-run check. Verify with a clean full `npm test`.

### F-02 — rc tags and version strings unsupported by release tooling — Important — window rc2–rc5

- Evidence: `scripts/set_version.py` `--update` uses
  `re.fullmatch(r"\d+\.\d+\.\d+", …)` so it cannot write `1.6.0-rc.1`;
  `.github/workflows/release.yml` matches tags `v[0-9]+.[0-9]+.[0-9]+`, so
  `v1.6-rc1` … `v1.6-rc10` do not trigger a publish. `set_version.py --check`
  still accepts the rc string because it only compares fields.
- Impact: rc stages cannot be version-bumped by the standard tool and cannot
  accidentally publish — the latter is desirable, the former is a workflow gap.
  Docs now warn agents not to "fix" the tag pattern to publish an rc.
- Fix idea: add explicit prerelease support to the script and a separate
  pre-release workflow only if the team wants rc artifacts; otherwise formalize
  the manual bump used in rc1 as the supported path.

### F-03 — Documentation version drift — Important — window rc2–rc5

- Evidence at baseline: `docs/AI-GUIDE.md` scope said `v1.5.4`, commit
  `1491f56` (one commit behind `f0d4cc2`); `wiki/AI-Contributors.md` version
  policy said production tag `v1.5.3`; `wiki/Recent-Updates.md` said current
  release v1.5.3 while `CHANGELOG.md` top was 1.5.4.
- Impact: agents and contributors can target the wrong baseline and reproduce
  against a stale commit.
- Status: AI-GUIDE, AI-Contributors, and CHANGELOG updated in rc1;
  `wiki/Recent-Updates.md` still needs a check before final release.

### F-04 — Lint warning backlog — Minor — window rc6–rc9

- Evidence: `npm run lint` exits 0 with 343 warnings (`no-unused-vars`,
  `no-explicit-any`).
- Impact: real warnings are lost in noise; not a correctness issue today.
- Fix idea: split into named cleanups by area, never a global `any` sweep in one
  commit.

### F-05 — Maintainer-untracked directories break format check — Minor — window rc6–rc9

- Evidence: root checkout has untracked `.planning/`, `.playwright-mcp/`, and
  three `docs/superpowers/{plans,specs}` files. `format:check` scans them and can
  fail; the isolated rc worktree passes (exit 0).
- Impact: local `format:check` results are misleading in the maintainer's
  checkout; CI on committed files is unaffected.
- Fix idea: extend `.prettierignore` for those paths, or keep checks in a clean
  worktree. Do not modify those untracked files.

### F-06 — Rust advisory unaddressed and no dependency-audit CI gate — Important — window rc2–rc5

- Evidence: `cargo audit` reports `url 2.5.8` with RUSTSEC-2026-0592 ("Stack
  overflow in `Url::origin()` on nested `blob:` URLs", fix `>=2.5.9`), plus six
  unmaintained/unsound advisories (`chrono`, `fxhash`, `instant`,
  `proc-macro-error`, `glib`, `rand`) currently allowed. `cargo tree -i url`
  shows it is transitive through `tauri 1.8.3` / `wry 0.24.12`, with no direct
  `Url::origin()` call in `src-tauri/src`. No `cargo audit` or `npm audit` step
  exists in any `.github/workflows/*`; CI relies on CodeQL and the npm/web jobs
  only. Log: `/tmp/opencode/hrt-1.6-rc-audit/cargo-audit.log`.
- Impact: a known stack-overflow advisory sits in the desktop dependency graph
  with no automated gate to catch future advisories; exploitability here is
  indirect (webview/Tauri), so this is not proven reachable from app code.
- Fix idea: try `cargo update -p url --precise 2.5.9` inside rc2–rc5 and verify
  Tauri still builds; add a scheduled/manual audit report step (not necessarily
  a blocking gate) to CI. Do not change the main vendor versions in rc1.

### F-07 — E2E default port can be blocked without a clear diagnostic — Minor — window rc6–rc9

- Evidence: `npm run test:e2e` failed to start its Worker webServer because
  `127.0.0.1:8787` was already occupied by an unrelated local process; the only
  signal was an esbuild `Address already in use` line. Re-running with
  `E2E_API_PORT=8899` passed 28/28 (`/tmp/opencode/hrt-1.6-rc-audit/e2e*.log`).
- Impact: a developer with a local Worker on the default port sees a confusing
  startup failure instead of a hint about `E2E_API_PORT`; no code defect was
  found — the suite is green on a free port.
- Fix idea: document `E2E_API_PORT` in the contributor guide and/or add a
  preflight check that names the conflicting port and the override.

### F-08 — Branch and commit-history accumulation — Minor — window rc6–rc9

- Evidence: `git branch` lists 117 local branches (116 unmerged into `main`),
  150 remote refs, and 14 tags. `git branch --no-merged main` includes parallel
  `security/*`, `refactor/*`, `feat/journal-*`, and `plan-*` lines. Main's 913
  commits contain 19 duplicated subjects from rebase/merge artifacts (e.g.
  `fix(security): harden deployment, auth throttling and request bodies`,
  `emergency fix`, `Revert "…"` pairs).
- Important negative result: the large "commits ahead" counts on the security
  branches are stale-fork artifacts, **not** missing fixes. Spot-checks confirm
  the behaviors are present in main: admin session revocation
  (`src/server/routes/admin.ts:651-684`), admin re-auth gate
  (`src/server/routes/admin.ts:30-32`), browser-side encryption enforcement for
  shares (`src/server/routes/shares.ts:69-74,217-220`), and share expiry to 2100
  (`src/server/routes/shares.ts:117`). Do **not** report these as unpatched.
- Impact: no user-visible defect today, but agents and new contributors can
  pick a stale branch as a baseline, reintroduce superseded code, or misread the
  duplicated history as two separate fixes. Audit scope becomes ambiguous.
- Fix idea: after rc10, archive/delete stale branches and add a short branch
  policy to `docs/AI-GUIDE.md` (main stable, rc line active, everything else
  historical). Do not delete branches during rc1–rc5.
